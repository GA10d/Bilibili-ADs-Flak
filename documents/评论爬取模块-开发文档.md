# 评论爬取模块 — 开发文档

## 一、需求概述

### 1.1 功能目标
从 B站视频评论区完整爬取一级评论及楼中楼回复，输出结构化数据，为后续 AI 广告识别提供数据源。

### 1.2 输入
- 单个 BV 号（CLI 直接传入）
- 批量 BV 号文件（`.txt`，一行一个 BV 号）

### 1.3 输出
每条评论包含以下字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `rpid` | int | 评论唯一ID |
| `parent_id` | int \| None | 父评论ID，一级评论为 None |
| `uid` | int | 评论者UID |
| `username` | str | 评论者昵称 |
| `content` | str | 评论文本内容 |
| `publish_time` | datetime | 发布时间 |
| `likes` | int | 点赞数 |
| `is_deleted` | bool | 是否已被删除 |

输出格式支持 JSON / CSV，按视频分文件存放于 `data/` 目录。

## 二、技术方案

### 2.1 技术选型

| 层面 | 选择 | 理由 |
|------|------|------|
| 语言 | Python 3.11+ | 与项目整体一致 |
| HTTP 客户端 | `bilibili-api-python`（优先）/ `requests`（fallback） | 前者封装了签名、分页，降低开发量 |
| 异步 | `asyncio` | 限速等待不阻塞，可扩展并发爬取多个视频 |
| 数据模型 | `pydantic` | 类型校验、序列化、与后续 AI 模块对接 |
| 日志 | `loguru` | 需求文档指定 |
| 配置管理 | `pydantic.BaseSettings` | 支持环境变量 + 配置文件 |

### 2.2 项目结构

```
src/
├── __init__.py
├── config.py              # 全局配置
├── main.py                # CLI 入口
└── crawler/
    ├── __init__.py
    ├── models.py           # 数据模型
    ├── crawler.py          # 核心爬虫
    └── checkpoint.py       # 断点续爬
data/                       # 输出目录
logs/                       # 日志目录
```

### 2.3 认证方案（双模式）

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| 匿名模式 | 无需 SESSDATA，直接请求 | 快速测试、低频使用 |
| Cookie 模式 | 传入 SESSDATA + bili_jct | 高频爬取，降低风控概率 |

实现方式：通过 `Config` 中的 `auth_mode` 字段切换。Cookie 模式下构造 `bilibili_api.Credential` 对象传入 API 调用。

## 三、B站评论 API 分析

### 3.1 一级评论

- **接口**：`GET https://api.bilibili.com/x/v2/reply/main`
- **关键参数**：
  - `oid`：视频评论区ID（通过 BV 号 → aid → oid 获取）
  - `type`：固定为 `1`（视频评论）
  - `mode`：排序方式，`3` = 热度排序
  - `next`：分页游标（首次请求传 `0`）
- **分页机制**：响应中 `data.cursor.next` 为下一页游标，返回 `0` 表示已到末尾
- **`bilibili-api-python` 封装**：`comment.get_comments(oid, type_, order, credential)`

### 3.2 楼中楼（子回复）

- **接口**：`GET https://api.bilibili.com/x/v2/reply/reply`
- **关键参数**：
  - `oid`：同上
  - `type`：同上
  - `root`：根评论 rpid
  - `pn`：页码（从 1 开始，每页最多 20 条）
- **分页机制**：响应中 `data.page` 包含 `num` / `size` / `count` 等分页信息
- **`bilibili-api-python` 封装**：`comment.get_replies(oid, type_, root, credential)`

### 3.3 BV号 → oid 转换

- BV 号通过 `bilibili_api.video.Video(bvid)` 获取 `aid`，再通过 `video.get_info()` 获取 `cvid`（即 `oid`）
- `bilibili-api-python` 内部已封装此转换

## 四、模块详细设计

### 4.1 数据模型（`src/crawler/models.py`）

```python
from pydantic import BaseModel
from datetime import datetime

class Comment(BaseModel):
    rpid: int
    parent_id: int | None = None
    uid: int
    username: str
    content: str
    publish_time: datetime
    likes: int
    is_deleted: bool = False
    replies: list["Comment"] = []     # 楼中楼子评论
```

- `replies` 为自引用列表，天然支持树形结构
- 支持 `.model_dump_json()` 直接序列化

### 4.2 配置（`src/config.py`）

```python
class Config(BaseSettings):
    # 认证
    auth_mode: str = "anonymous"      # "anonymous" | "cookie"
    sessdata: str | None = None
    bili_jct: str | None = None

    # 爬取
    max_reply_depth: int = 2          # 递归深度（1=仅一级评论）
    delay_base: float = 1.5           # 基础延时（秒）
    delay_jitter: float = 0.5         # 随机抖动（秒）

    # 输出
    output_dir: str = "data"
    output_format: str = "json"       # "json" | "csv"

    # 检查点
    checkpoint_dir: str = "data/checkpoints"

    # 日志
    log_dir: str = "logs"
```

### 4.3 检查点管理（`src/crawler/checkpoint.py`）

```python
class CheckpointManager:
    """管理每个视频的爬取进度"""
    state: dict[str, dict]  # {"BV123": {"top_cursor": 456, "completed": false}}

    def load_checkpoint(self, bv_id: str) -> dict | None
    def save_checkpoint(self, bv_id: str, cursor: int, completed: bool) -> None
    def is_completed(self, bv_id: str) -> bool
    def get_cursor(self, bv_id: str) -> int
```

- 状态文件：`data/checkpoints/<bv_id>.json`
- 每爬完一页立即写入（最小化中断损失）
- 启动时加载所有 checkpoint 文件

### 4.4 核心爬虫（`src/crawler/crawler.py`）

```python
class CommentCrawler:
    """单个视频的评论爬虫"""

    def __init__(self, config: Config):
        ...

    async def crawl(self, bv_id: str) -> list[Comment]:
        """完整爬取一个视频的所有评论（含楼中楼）"""
        1. 加载 checkpoint，确定起始 cursor
        2. 将 BV 号转为 oid
        3. 循环拉取一级评论（分页，限速）
        4. 对每条 reply_count > 0 的评论，递归拉取楼中楼
        5. 每次翻页保存 checkpoint
        6. 全部完成后标记 completed

    async def _fetch_top_comments(self, oid: int, start_cursor: int) -> AsyncIterator[list[dict]]:
        """按页拉取一级评论，支持断点续爬"""

    async def _fetch_replies(self, oid: int, root_rpid: int) -> list[dict]:
        """拉取某条一级评论的所有楼中楼回复"""

    def _parse_comment(self, raw: dict, parent_id: int | None = None) -> Comment:
        """将 API 返回的原始数据转为 Comment 模型"""

    def _rate_limit(self) -> None:
        """延时：base_delay + random(0, jitter) 秒"""
```

**核心流程伪代码**：

```
async crawl(bv_id):
    checkpoint = checkpoint_manager.load(bv_id)
    cursor = checkpoint.get("top_cursor", 0)

    oid = await bv_to_oid(bv_id)

    while cursor != 0:
        page = await api.get_comments(oid, type=1, next=cursor)
        for raw_comment in page["replies"]:
            comment = parse_comment(raw_comment)
            if raw_comment["reply_count"] > 0:
                comment.replies = await fetch_replies(oid, comment.rpid)
            comments.append(comment)

        cursor = page["cursor"]["next"]
        checkpoint_manager.save(bv_id, cursor, completed=(cursor == 0))
        await rate_limit()

    return comments
```

## 五、错误处理

| 场景 | 处理策略 |
|------|---------|
| 网络超时 | 重试 3 次，指数退避（1s → 2s → 4s） |
| API 风控（412） | 等待 60s 后重试，最多 3 次 |
| 无效 BV 号 | 记录错误日志，跳过，继续处理下一个 |
| Checkpoint 文件损坏 | 删除该 checkpoint，从头重新爬取 |
| 输出目录不存在 | 自动创建 |

## 六、GUI 对外接口

> **设计原则**：爬取模块是**库**，而非单纯的 CLI 工具。`main.py` 只是该库的一个薄封装。
> GUI 和 CLI 共享同一套 API，区别仅在于**进度回调**的呈现方式（终端进度条 vs 图形进度条）。

### 6.1 架构分层

```
┌─────────────────────────────────────────┐
│  GUI (PyQt / Tkinter / Web)             │  ← 调用 CrawlerService
├─────────────────────────────────────────┤
│  CLI (main.py)                          │  ← 调用 CrawlerService
├─────────────────────────────────────────┤
│  CrawlerService      ← 统一对外门面     │
│  ├─ CommentCrawler   ← 核心爬取逻辑     │
│  ├─ CheckpointManager← 断点管理         │
│  ├─ Config           ← 配置             │
│  └─ Models           ← 数据模型         │
└─────────────────────────────────────────┘
```

### 6.2 核心服务类 `CrawlerService`

GUI 仅需与此类交互，无需触碰内部实现。

```python
class CrawlerService:
    """爬取模块对外统一入口。CLI 和 GUI 共用。"""

    # ============ 配置 ============
    def update_config(self, **kwargs) -> None:
        """动态更新配置项（如超时、限速等），运行时即时生效"""
        # 例如: service.update_config(delay_base=2.0)

    def get_config(self) -> Config:
        """获取当前生效的全部配置"""

    # ============ 视频信息 ============
    async def get_video_info(self, bv_id: str) -> VideoInfo:
        """查询视频基本信息（标题、评论总数、封面），不爬取评论"""

    # ============ 爬取 ============
    async def crawl(
        self,
        bv_id: str,
        on_progress: Callable[[ProgressEvent], None] | None = None,
    ) -> CrawlResult:
        """爬取单个视频的全部评论"""

    async def crawl_batch(
        self,
        bv_ids: list[str],
        on_video_progress: Callable[[ProgressEvent], None] | None = None,
    ) -> list[CrawlResult]:
        """批量爬取多个视频（串行），每个视频完成后回调"""

    # ============ 控制 ============
    def cancel(self) -> None:
        """发送取消信号，当前爬取任务在下一页请求前停止"""

    # ============ 断点 ============
    def list_checkpoints(self) -> list[CheckpointInfo]:
        """列出所有已保存的断点"""

    def remove_checkpoint(self, bv_id: str) -> None:
        """删除指定视频的断点（下次从头爬取）"""

    def clear_all_checkpoints(self) -> None:
        """清空全部断点"""
```

### 6.3 进度事件 `ProgressEvent`

```python
@dataclass
class ProgressEvent:
    bv_id: str                    # 当前视频 BV 号
    phase: str                    # "fetching_top" | "fetching_replies" | "saving" | "completed"
    current_page: int             # 当前页号
    page_size: int                # 每页条数
    total_crawled: int            # 已爬取评论数（含楼中楼）
    estimated_total: int | None   # 估算总数（来自 API 返回），可能为 None
    message: str                  # 人类可读进度描述
```

GUI 使用方式示例（伪代码）：

```python
def on_progress(event: ProgressEvent):
    # 更新进度条
    progress_bar.setMaximum(event.estimated_total or 0)
    progress_bar.setValue(event.total_crawled)
    # 更新状态文本
    status_label.setText(event.message)
    # 强制刷新事件循环
    QApplication.processEvents()
```

### 6.4 结果类型

```python
@dataclass
class CrawlResult:
    bv_id: str
    video_title: str

    total_count: int              # 实际爬到的评论总数

class CheckpointInfo:
    bv_id: str
    cursor: int

    saved_at: datetime
```

### 6.5 GUI 典型交互流程

```
1. 用户输入 BV 号
2. GUI 调用 service.get_video_info(bv_id) → 显示视频标题 + 评论总数
3. 用户调整配置并点击"开始爬取"
4. GUI 调用 service.crawl(bv_id, on_progress=update_ui)
5. 爬取过程中，回调函数实时更新进度条、当前页数、已爬条数
6. 用户可随时点击"取消" → 调用 service.cancel() → 当前页完成后停止并保存断点
7. 完成后拿到 CrawlResult，GUI 在表格中展示评论列表
8. 用户可点击"保存" → 由 GUI 负责序列化（Comment 模型自带 .model_dump_json()）
```

### 6.6 接口契约总结

| 接口 | 用途 | 谁调用 |
|------|------|--------|
| `CrawlerService.update_config()` | 运行时改配置 | GUI 设置面板 |
| `CrawlerService.get_video_info()` | 预览视频信息 | GUI 确认页 |
| `CrawlerService.crawl()` | 爬单个视频 + 进度回调 | GUI 主流程 |
| `CrawlerService.crawl_batch()` | 批量爬取 | GUI 批量模式 |
| `CrawlerService.cancel()` | 中断爬取 | GUI 取消按钮 |
| `CrawlerService.list_checkpoints()` | 查看断点列表 | GUI 断点管理页 |
| `CrawlerService.remove_checkpoint()` | 删除单个断点 | GUI 断点管理页 |
| `ProgressEvent` | 进度推送 | 回调函数消费 |
| `CrawlResult` | 爬取结果 | GUI 展示 / CSV导出 |
| `VideoInfo` | 视频信息 | GUI 预览 |
| `CheckpointInfo` | 断点信息 | GUI 断点列表 |
